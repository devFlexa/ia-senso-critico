01 • Mentalidade

IA é copiloto, não piloto automático.

Se você não consegue explicar o código que entregou, o trabalho ainda não terminou.

❌ USO FRACO

02 • Processo

Método P.E.N.S.E.

P — Pergunte bem.
Informe linguagem, objetivo, o que você tentou e o erro encontrado.
E — Entenda a resposta.
Peça explicações. Procure palavras, funções ou conceitos que você não conhece.
N — Navegue pelo código.
Siga variáveis, condições, funções e fluxo de execução.
S — Simule e teste.
Execute. Troque entradas. Tente quebrar a solução. Observe os erros.
E — Explique com suas palavras.
Se você consegue explicar e modificar sem copiar tudo novamente, houve aprendizagem.

04 • Laboratório

Agora você é o revisor da IA 🕵️

Não abra o gabarito primeiro. Analise, marque o que verificou e escreva sua conclusão.

Desafio 1 — O código parece correto?

A IA afirmou que o código abaixo mostra apenas números maiores que 20:

let valores = [10, 15, 14, 50, 60, 70];

let maiores = valores.map((v) => v > 20);

console.log(maiores);

Minha análise:

Gabarito: map() transforma cada item e, nesse caso, gera valores booleanos: [false, false, false, true, true, true]. Para selecionar elementos que atendem a uma condição, use filter(): valores.filter(v => v > 20). O ponto importante não é decorar: map transforma; filter seleciona.

Desafio 2 — Funciona, mas é seguro?

A IA sugeriu este login:

const usuario = "admin";
const senha = "123456";

if (usuario === "admin" && senha === "123456") {
  console.log("Acesso liberado!");
}

Minha análise:

Gabarito: a comparação funciona como demonstração de lógica, mas não é um sistema de autenticação seguro. Credenciais não devem ficar expostas no código do front-end. Em uma aplicação real, autenticação envolve back-end, armazenamento apropriado de senhas (hash), transporte seguro e controles de acesso. Código que executa não é automaticamente código pronto para produção.

Desafio 3 — Teste casos que a IA esqueceu

function dividir(a, b) {
  return a / b;
}

console.log(dividir(10, 2));

A resposta 5 está correta. Isso significa que a função está pronta?

Minha análise:

Gabarito: um único teste não comprova que a função lida bem com todos os casos. Vale testar zero, negativos, decimais e entradas inválidas. O comportamento desejado também precisa ser definido. Programar é pensar nos casos que não aparecem no exemplo perfeito.
